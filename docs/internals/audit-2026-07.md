# Codebase audit — July 2026

**A dated snapshot, not a specification.** Assessed against `v1.17.0` /
`ba2eaa1`. The evergreen description of the system is
[architecture.md](architecture.md); this file is the opinion layer, kept
separate so it can go stale without dragging that one with it.

**When an item ships, delete it here** and fold the outcome into
`architecture.md`. If this file is more than a few months old, trust the code
and the issue tracker over it.

Claims are marked **[verified]** where they were confirmed by reading the source
during the audit, and **[reported]** where they come from the survey and still
need a first-hand check before anyone acts on them.

---

## The short version

The firmware works. The bench device logged 468,488 polls with zero timeouts and
zero transmit failures in the 18 minutes after an OTA, and
[poll_log.md](poll_log.md) records the same clean result over 25M requests. The
fork's own components are well built.

The exposure is not the inherited dead code. It is, in order:

1. **The storage layer will erase the product's only deliverable** on the
   failure most likely to happen to it (§1).
2. **Three roadmap items are about to be built on four competing definitions of
   "engine off"** (§5).
3. **The code that changes most often has no host tests** (§4).

Everything else — the parser panic, the dead subsystems, the CI gaps — is real
but absorbable at leisure.

## 1. Storage robustness — the actual Tier 0

Filed as **[#71](https://github.com/cdufresne81/nc-flash-wican-fw/issues/71)**.

**[verified]** `.format_if_mount_failed = true` (`sdcard.c:198`, `:251`), with
`USE_SD_FATFS` defined unconditionally (`hw_config.h:30`). A FAT corrupted by
abrupt power loss — key-off, battery pull, cranking brownout — means the next
boot **silently reformats the card**: every trip CSV and every staged ROM gone.
The CSV writer `fsync`s frequently (`csv_logger.c:285-286`, `:672-673`,
`:749-750`), which is right for row durability but maximises the window in which
a power cut lands mid-metadata-update.

**[verified]** No runtime recovery. `sd_card_init()` runs once (`main.c:577`);
`sdcard_is_mounted()` returns a static set at `sdcard.c:282` and cleared only in
deinit (`:314`). A card that glitches mid-drive leaves the writer retrying
against a dead mount every 5 s forever with no remount
(`csv_logger.c:654-662`). `SDCARD_DETECT_PIN` is configured at `main.c:573-575`
and never read again.

**[verified]** No free-space policy — the only `esp_vfs_fat_info()` call is
`sd_filemgr.c:391`, for display.
**[reported]** On a full card this is believed to produce an empty file every
few seconds rather than a clean refusal.

**[verified]** The SD un-brick path wipes configuration:
`sdcard_perform_ota_update()` calls `filesystem_delete_config_files()`
(`sdcard.c:54-57`) before flashing, so using the recovery path costs the user
their Wi-Fi setup. Possibly intended; documented nowhere.

**[verified]** Power loss during an ECU flash has no story. `FLASH_ACTIVE_BIT`
is RAM, so after a brownout mid-`TransferData` the device boots clean and
cheerful while the ECU sits half-erased. The codec already tracks progress
(`NCFWPROG` every 16 blocks, `ncflash_fastwrite.c:52`); stashing "flash in
progress, block N" in `RTC_NOINIT` and replaying it at boot — exactly what
`crash_report.c` already does for panics — turns the worst support call into a
diagnosis. Roughly ten lines.

## 3. The config parser — one class fix, not twelve spot fixes

`config_server_parse_cfg_into()` is **839 lines** (`config_server.c:2158-2996`),
23% of a 3,718-line file, and
is roughly fifty repetitions of:

```c
key = cJSON_GetObjectItem(root,"can_mode");
if(key == 0)                  { goto config_error; }
if (key->valuestring == NULL) { goto config_error; }
strlcpy(dst->can_mode, key->valuestring, sizeof(dst->can_mode));
ESP_LOGI(TAG, "dst->can_mode: %s", dst->can_mode);
```

A declarative key table — name, struct offset, size, required/optional, type,
validator, **secret flag** — collapses this to a table plus one loop.

**This subsumes 2.1 and 2.5.** Fixing twelve NULL sites by hand and *then*
rewriting the same 839 lines means bench-validating the boot path twice. If the
panic must close before the table lands, the stopgap is a single shared
`cfg_get_str(root, key, dst, size, default)` helper — which is literally the
first row of the refactor, done incrementally — not twelve spot patches.

Acceptance is the round-trip invariant: a browser load → save → revert must
leave `/load_config` byte-identical (documented exceptions in
[web_ui.md](web_ui.md)), plus a bench OTA.

Let the key table live in **its own file**. `config_server.c` mixes a config
store, a status-JSON builder, 17 handlers and reboot scheduling; the eventual
split is config-store vs HTTP-server. Do not do that split speculatively — but
put the seam in now, for free, while you are there.

## 4. Host tests for the decode core

The most-changed code in the repo has no automated test, and it is all pure C
with trivially stubbed dependencies:

- `polllog_req_bytes()`, `polllog_match()`, `polllog_prepare_schedule()`
  (`poll_log.c:298-706`)
- `evaluate_expression()` (`expression_parser.c`)
- `calc_evaluate()` (`autopid.c:504-687`)

Every recent feature landed inside them — #29 divisors, #51 Mode 23, #61 A/B/C
forms — and each was validated with bench hours. The divisor scheduling was
verified *arithmetically on the device over 924 sweeps*. That is a unit test
begging to exist.

A `tools/hosttest/` target turns future protocol changes from bench-hours into
milliseconds, and is a **hard prerequisite for the #28 autopid split**, which
relocates precisely this code. (The repo already declares `unity` as a phantom
dependency — see §6.)

`tools/webtest/` now covers the JavaScript side's exact-inverse pairs; this is
the C-side equivalent and it matters more.

## 5. The power-state seam — design this before #2, #4 or #24

Issues **#2** (upload after engine stop), **#4** (light-sleep duty cycle) and
**#24** (battery guard) all need the same notion: *engine off → grace window →
parked → periodic wake*.

Today there are **four independent engine/power state machines**:

| Source of truth | Where |
|---|---|
| voltage ignition gate | `vehicle.c`, consumed at `csv_logger.c:591-614` |
| CAN-derived quiesce | `poll_log.c:1114-1191` |
| sleep_mode's own voltage machine | `sleep_mode.c` |
| the CSV close debounce combining two of the above | `csv_logger.c` |

Bolt each roadmap item onto a different one and the interactions become
undebuggable: #2's upload must hold off #4's sleep, which must not fight
poll_log's LISTEN_ONLY, while #24's periodic wake must not open a CSV session.

**The missing module is a single fork-owned power/trip-state authority** —
states `RUNNING` / `KEY_OFF_GRACE` / `PARKED` / `GUARD_WAKE`; inputs poll_log
quiesce + voltage; consumers CSV close, uploader, sleep, guard — using the same
registration seams as everything else (`architecture.md` §9). Design it before
the first of the three lands. Among them, **#4 goes first**: it defines the
power budget the other two spend from.

Related: **#3 (live streaming) needs one seam cut, named now.**
`csv_emit_wide_row()` composes the row and `fprintf`s it in one function
(`csv_logger.c:345-441`). Streaming needs the composed row *without* the file.
The cut is compose-vs-sink (a row-sink callback list; the SD file becomes sink
one). Cheap at #3 time, expensive if anyone meanwhile optimises compose and
write closer together.

## 6. Dead weight

Lowest-value tier — dead code that never executes costs reading time, not
runtime. **Do this after §1, §3 and §4**, not before. Issue **#28** is the
ledger, but the ledger is itself incomplete: its MQTT claim is wrong, its
`Period` note is obsolete, **every one of its file:line citations has drifted**,
and it omits the largest item below.

| Dead thing | Size | Note |
|---|---|---|
| **SmartConnect** | `smartconnect.c` 732 + `.h` 87 | An entire second Wi-Fi manager, reachable only by hand-editing `wifi_mode`. **Absent from #28.** Drags 10 passthrough config keys, a priority-5 8 KB task, and the whole IMU chain. |
| non-PRO half of `elm327.c` | **1,232 lines** (`:65-1296`) | A complete software ELM327 emulator. 37% of the file, and the only place an ELM327 command reaches TWAI — which is why reading it cold gives the wrong model of the hardware. |
| `main/console.c` | **1,166 lines** | Compiled, entirely unreferenced duplicate of `components/cmdline`. Awkwardly it has features cmdline lacks (history, arrow keys) — so decide *which* to keep rather than deleting blind. |
| non-PRO half of `sleep_mode.c` | ~524 lines (`:61-584`) | Also the sole reason the `mqtt` dependency cannot simply be dropped. |
| the **IMU chain** | driver + task + IRAM ISR | Runs unconditionally for a consumer that never runs. Its configured threshold is discarded anyway: `config_server_get_imu_threshold()` is called at `main.c:652`, **163 lines before the config is loaded** at `:815`. **[verified]** |
| `/scan_available_pids`, `/std_pid_info` | 2 endpoints | Nothing in `main.js`, the page or `tools/` fetches them. (`tools/nc_datalogger/README.md:55` *mentions* `scan_available_pids`, so they are not entirely undocumented — just uncalled.) |
| `mqtt`, `unity`, `spiffs`, `esp_http_client`, `esp-tls`, `wear_levelling` | **0 bytes linked each** | Phantom entries in `main`'s `REQUIRES`. **#28's "MQTT costs flash" claim is wrong** — it costs build time and confusion. |
| `vehicle_profiles/` + tooling | 25 tracked files (20 + 5 in `.vehicle_profiles/`) | **Ten** non-Mazda manufacturers — bmw, byd, hyundai, jaguar, kia, nissan, opel, renault, toyota, vw — and `vehicle_profiles_validate.yml` burns CI on **every PR**. |

⚠️ **`mqtt` removal and #24 are one decision, not two.** The stated blocker is
`#include "mqtt_client.h"` at `sleep_mode.c:47` — note that this sits in the
**always-compiled preamble**, *above* the `#if HARDWARE_VER != WICAN_PRO` at
`:61`, which is precisely why the dependency survives even though everything
that uses it is in the dead half. But the real
blocker is that #24's alert transport is undecided and upstream's answer was
MQTT (`sleep_mode.c:471-514`). Decide the transport for #24 first, then delete
`mqtt` once.

**Dependency graph** — five two-node cycles (`main` ↔ each of `autopid`,
`csv_logger`, `fast_log`, `sd_filemgr`, `cmdline`), `autopid` using five
undeclared components, and `main/icm42670.h` leaking a `PRIV_REQUIRES` header
through a public one. See `architecture.md` §9.

Costed options, not recommendations.

## 10. What not to do

As important as the do-list, because an agent will act on this document.

1. **Do not convert the free-running sweep to a timer/period scheduler.**
   Tactrix-style millisecond periods look "more correct"; the
   one-request-in-flight self-pacing design is *why* the record is 0 timeouts
   over 25M requests. The sweep **is** the scheduling quantum. Defend it.
2. **Do not spot-fix the twelve parser NULL sites** — do the class fix (§3).
3. **Do not `esp_restart()` on early-boot allocation failure** (2.6).
4. **Do not enable OTA rollback as a drive-by** (2.7).
5. **Do not do the #28 autopid split before host tests exist** (§4).
6. **Do not half-add HTTP auth or `/check_status` redaction.** And keep
   perspective: port 35001 accepts any LAN client and `NCFW_ALLOW_LIVE = 1`
   (`ncflash_fastwrite.c:32`) means anyone on the network can start a live ECU
   write of a staged ROM. **The security boundary of this product is Wi-Fi
   association.** Auth theatre on port 80 changes nothing until that is
   rethought deliberately.
7. **Do not add core pinning.** Nothing measured wants it, and it invites
   "these two cannot race" reasoning that the current no-affinity design
   correctly forbids.
8. **Do not touch the boot order, or the whitelist `memcpy`-before-parse**
   (`config_server.c:871`). Both look redundant; both are load-bearing
   (`architecture.md` §8b).
9. **Do not componentise `ncflash_*` / `slcan_port.c`.** They share `types.h`,
   the queue globals and `can_tx_task`'s execution context with `main`.
   Cosmetic moves in the brick path are negative value.

## 11. What is already good

Listed because a refactor can destroy these by accident.

- **The fork's own components are well built.** `poll_log.c` has zero
  commented-out lines and explains its reasoning — including what was tried and
  rejected — at the site of each decision. That habit is why #29, #51 and #56
  could be built on it safely.
- **The registration seams are the right abstraction.** `csv_logger` not
  linking against a protocol component *for records* is what let hybrid capture
  and Mode 23 land without touching the writer.
- **The two-flag bus interlock is subtle and correct.** Codec-owned
  `FLASH_ACTIVE_BIT` separated from the host-owned claim, and the reaper's
  refusal to touch the former. Do not "simplify" it into one flag.
- **Measuring instead of estimating.** The Auto CSV grid tracks a measured
  sweep rate, which is what makes it correct under hybrid capture and divisors.
  (The one lapse is the UI's sweep predictor — issue #67.)
- **`crash_report` is exemplary**: its declared dependency graph is exactly
  right, and its link-time `--wrap` reaches the final app link.
