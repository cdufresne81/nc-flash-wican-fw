# v1.23.0 - One mode, and it cannot be taken away from you

The adapter now has exactly one mode: the **Datalogger**. It is built into the firmware. Nothing can change it - not a setting, not a config file you upload, not a tool on your PC, not a bad value left behind by something that crashed.

## The problem

The adapter used to read a word out of its config file to decide what to do: `poll_log` for the Datalogger, or `slcan`, `elm327`, `fast_log` for other things. If that word ever ended up wrong, the adapter stopped logging and looked completely healthy while doing it - Wi-Fi connected, SD card mounted, no errors. You only found out when the drive produced no data. Getting it back meant downloading the config file, editing one word by hand, and uploading it again.

That happened for real (issue #92). And it was never something you did - it was the PC tool writing the word.

Worse, the code that read that word had a trap in it. It compared against four known values, and **anything it did not recognise fell through to a mode where the datalogger does not run**. A typo, a half-written file, a word from a newer firmware - any of those quietly killed logging.

## The fix

The word is gone. The adapter does not read it, so nothing can set it wrong.

- The `protocol` setting no longer exists. Upload a config that says `slcan`, or `elm327`, or `potato` - the adapter accepts the file, ignores that line, and runs the Datalogger.
- The `port` and `port_type` settings no longer exist either, along with the CAN-over-TCP server they configured. That server only ever carried the retired modes, so nothing produced data for it and nothing read data from it.
- The **CAN** section is gone from Settings. There was nothing left in it that did anything.
- The "Restore Datalogger mode" button and its warning banner are gone. They existed to rescue a device stuck in the wrong mode, and that cannot happen any more.

**Flashing your ECU is completely unaffected.** NC Flash talks to the adapter on a fixed, always-on channel that has nothing to do with any of this, and it was not touched. It never needed the mode switch.

## What this means for NC Flash

**You need NC Flash v2.9.0 or newer.** Older versions worked by switching the adapter into `slcan` mode - there is nothing to switch into now, so they cannot reach your ECU at all. They fail cleanly; they cannot half-write your engine computer. But they will not work.

If you are on v2.9.0 or newer, nothing changes. It already flashes without touching the mode.

## Two things to know before you upgrade

**Going back to older firmware needs care.** The old firmware refuses to load a config file that is missing certain lines, and when it refuses it wipes the file and starts fresh - which would take the adapter off your Wi-Fi. To stop that, this firmware still writes those lines into the file, at fixed values, purely so an older build can still read it. They do nothing.

**That safety net is temporary. It is removed in v1.25.0.** From that version on, a backup you take can only be restored on v1.23.0 or newer. The downloaded file says so itself, in a `_deprecated` line, so you do not have to remember it.

## How it was tested

On the bench adapter, over Wi-Fi:

- Wrote `"protocol":"slcan"`, `"port":"35001"`, `"port_type":"udp"` into the adapter's real config file - the file it reads at startup - and rebooted it. It came up as a working Datalogger, polling the engine computer. **The failure from issue #92 is now impossible rather than repaired.**
- The ECU flashing channel answered normally afterwards.
- The old CAN-over-TCP port refused connections, as intended - the server is gone.
- Two reboots, **zero unexpected resets**, SD card mounted throughout.
- Every setting survived: Wi-Fi, access point, sleep voltage, sleep time, engine voltage, wake-on-CAN, time zone.
- A config downloaded and uploaded back unchanged restored everything, including all seven saved passwords.

Roughly 550 lines of code were deleted. The files that carry out an ECU flash were not touched at all.
