If you have ever come back from a drive to find the adapter recorded **nothing**, and rebooting it did not help — this release fixes the cause. It also adds a page that finally explains why your Wi-Fi keeps dropping.

## The recorder stopped starting by itself

This was reported against v1.18. The symptom was very specific and very confusing: automatic recording stopped happening at engine-on. Pressing **Start** by hand still worked. Rebooting the adapter did not help. **Only unplugging it from the OBD port fixed it.**

### What was wrong

Three separate things, each one hiding the next.

**It took over twenty seconds to start, and said nothing while it did.** On power-up the adapter waited 20 seconds before it even created the part of itself that writes to the SD card. Nothing on the page said "starting" — it just said **Idle**. There is no way to tell "still waking up" apart from "broken", so people did the reasonable thing and rebooted.

**Rebooting during that window broke it for the rest of the trip.** The adapter has a safety catch: if it crashed the last time it tried to start recording, it skips recording on the next start-up rather than crash again in a loop. Because of the 20-second wait, that catch was armed for roughly the first 35 seconds of *every* power-up — so a reboot at the 25-second mark looked exactly like a crash. The next start-up then skipped recording entirely.

And this is the part that explains the strange cure: the note saying "last attempt failed" lives in memory that **survives a reboot but not a power cut**. That is precisely why rebooting did not help and unplugging did.

**None of it was visible.** The skip was written only to the developer log, which is switched off on a shipping adapter. On a device with no serial console it reached nobody.

There was a fourth, unrelated latch found in the same report: pressing **Stop** by hand switched recording off until the next reboot. One log showed an ignition-on with 104 seconds of driving recorded to nothing because Stop had been pressed on the previous trip.

### What it does now

**Recording starts in about three seconds, not twenty-three.** The writer starts immediately; the only thing still held back is the first write to the SD card, by 10 seconds, because that is the one genuinely risky step. In practice the first log file opens as soon as the car's computer answers.

**A skipped start-up recovers by itself.** Instead of giving up for the whole trip, the adapter tries once more 60 seconds later. Only if that also fails does it stop for that power-up — which is the boot-loop protection actually doing its job, rather than a reboot being mistaken for a crash.

**It tells you.** The recorder card on the Status page no longer says *Idle* when it is not idle. You now get one of:

> Auto-start skipped — retrying in 47s
>
> Auto-start disabled this boot — press Start, or power-cycle the dongle
>
> Datalogger did not start — press Start, or power-cycle

and a matching line in the event log:

```
WARN  datalog auto-start SKIPPED -- previous attempt did not survive its first 15s
      (reboot or crash); retrying shortly
```

**Stop is now per-trip.** Press Stop and it stops that trip. Switch the ignition off and automatic recording arms itself again, with a line in the log to say so. (Force-**on** deliberately still survives, because bench work needs it to.)

**And the recording rule itself is now pinned in place.** The decision logic that starts and stops the recorder was pulled out into its own file with a set of tests that run on every change — including a truth table for the recording gate, and a replay of exactly the failure above. That gate is unchanged since v1.17.3 and now cannot drift without a test failing.

## A page that tells you why your Wi-Fi dropped

When the Wi-Fi link drops, the radio hands the firmware a reason code saying precisely why. Until now the firmware wrote it to a log nobody can read and threw it away. By the time you noticed "it dropped again", the one useful fact was already gone.

There is now an **Open diagnostics** button on the Status tab. It opens a page with:

- **A live signal trace**, sampled every second.
- **Every disconnect, with its reason in plain English** — not a number to look up.
- **Link stability**: how much of the time you were actually connected, how long the longest unbroken session was, how long connecting takes.
- **A findings panel that says what the numbers mean.** For example: that power save is costing you throughput; that the adapter's own hotspot is on a different channel from the network it joined; that the signal averaged −78 dBm and is at the edge of usable; that the access point negotiated 802.11b only, capping the link at 11 Mbit/s. If nothing is wrong, it says so.

**Drops are recorded permanently.** They now go into the event log on the SD card, so they survive reboots and cover unattended driving — the case where nobody has a browser open to watch.

**There is a report you can paste into a bug report.** A **Download report** button produces a text summary with your network name and the tail of your router's address **masked by default**. Your Wi-Fi password is never read by this code at all.

The page is a real page with its own address, not a pop-up — so reload works, you can open it on a phone, and it stays readable when the Wi-Fi it rides on is the thing failing. If it loses contact with the adapter it freezes the last values and says so rather than going blank.

Two honest limits. This is **diagnostic only** — it reports the link's condition and deliberately changes no Wi-Fi behaviour, so that we keep the ability to say what "before" looked like. And there is **no speed test**: it never pushes bytes through the link on purpose, so "slow transfer" is still diagnosed indirectly from signal, channel and link rate.

## Who this affects

Everyone, and **your saved settings are kept exactly as they are.** Nothing needs reconfiguring.

If your adapter had stopped auto-recording, this release fixes it and you do not need to unplug it any more.

One thing worth knowing: the diagnostics page adds about **54 KB** to the firmware. The partition it lives in is now 54% full, so there is plenty of room.

## Tested

Both changes were flashed and run on a real adapter.

**Recording:** the failure was replayed against the old logic and reproduced — 7 checks failed. With the fix, 60 checks pass. Five scenarios run automatically on every change: the reboot-inside-the-safety-window failure, the Stop latch, the boot-loop limit, the recording-gate truth table, and the countdown arithmetic including the point where the millisecond counter wraps around.

**Wi-Fi diagnostics:** the very first report generated on real hardware exposed five faults in the tool's own output, all fixed before merge — the timeline printed the network name into a report whose header promised it was masked; the low-memory warning used a threshold that fired on every healthy device, always; a throughput note was hardcoded from the wrong build configuration; "longest session 0s" showed on a device connected for five minutes; and a "lowest seen" memory figure came out higher than the current one. The first two now have tests, and the masking guard was checked by deliberately reintroducing the old bug and confirming the test catches it.

**Still unverified:** the Wi-Fi findings rules have only been observed on a *healthy* adapter. None of them has yet been seen firing on a unit that actually has the problem it describes.

## Known and not fixed here

The same safety-catch pattern — one crash costing a whole power-up, invisibly — also exists in the other three recorders (the fast log, the poll log and the event log itself). Fixing it there means sharing the mechanism, which is the right change but a separate one: automatically retrying those would mean restarting parts of the CAN interface mid-drive, and there is no field report asking for it yet.

## Installing

Upload `wican-fw_obd_pro_v1_19_0.bin` through the adapter's web page (**System → Firmware Update**). It restarts itself when done and your settings are kept. The other files are only needed for a full serial flash.
