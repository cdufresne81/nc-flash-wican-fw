# v1.22.0 - Flashing an ECU no longer gives up halfway

The headline fix in this release stopped a real ECU from being left unbootable. If you flash your car with NC Flash, update both: this needs **NC Flash 2.13.0** to work.

## The flash fix

When you flash a ROM, the ECU has to wipe its own memory before it can accept the new one. It goes completely silent while it does that — and on a full ROM it stays silent for about **12 seconds**.

The adapter only waited **5 seconds**, then declared the ECU dead and walked away. The ECU had already erased itself at that point, so it was left with nothing to run. An ignition cycle did not bring it back; only a full re-flash did.

The adapter now waits up to **60 seconds** at that moment, and NC Flash waits **90**. Measured on a real PCM, the wait is 12.6 seconds, so there is roughly four times the margin needed. The event log now records the real number each time:

```
waited 12.6 s while the ECU cleared its memory for the new ROM
```

Nothing else waits longer. Everywhere except that one moment, a missing answer is still a genuine fault and the adapter still fails fast — a flash cannot be resumed mid-stream, so being slow to notice a real problem would be worse, not better.

## Sleep no longer interrupts you

**The adapter used to fall asleep in the middle of an NC Flash session.** Reading fault codes, reading RAM, the unlock step before a flash — none of these counted as "busy", so the sleep countdown armed and the adapter dropped its Wi-Fi mid-job. It comes back in a couple of seconds, but your connection is gone by then.

It now stays awake for as long as a host tool is actually working, and the countdown is not even armed — so the page no longer tells you "Device will sleep in 0:34" for a sleep that was never going to happen.

**A related bug could cut a flash short.** The adapter has a 30-minute safety limit for a flash that appears stuck, and a stale timestamp could make a perfectly healthy flash look hours old, firing that limit immediately and pulling the CAN bus out from under a live ECU write. Fixed.

## Rescue button for a stuck adapter

If a flash session is interrupted at the wrong moment, older firmware could leave the adapter in **Bench SLCAN** mode, where it silently stops recording your drives — forever, until you noticed. Getting out meant downloading the config file, hand-editing one line, and uploading it back.

The warning banner on the Logger tab now has a **Restore Datalogger mode** button. It checks with the adapter first and **refuses** while a flash or a host session is live, because rebooting then is exactly what half-writes an ECU.

## The event log speaks plainly

A wording pass over the whole log. Nothing changed about how the adapter behaves.

- **`OTA` is now `UPDATE`.** The update line names the **file you uploaded** instead of an internal slot number.
- Lines no longer repeat their own label — `IGNITION_ON  ignition on -- ECU answering` is just `ECU answering`.
- **Failures that were coloured green are now amber**, including the crash headline and the three "resume failed, rebooting" lines. That was actively misleading.
- The Wi-Fi connect line now carries the signal strength.

## Install

**Over Wi-Fi (recommended):** open the device page, go to **System → Update Firmware**, upload `wican-fw_obd_pro_v1_22_0.bin`.

**Over USB (serial):** `bootloader.bin` at `0x0`, `partition-table.bin` at `0x8000`, `ota_data_initial.bin` at `0xd000`, `wican-fw_obd_pro_v1_22_0.bin` at `0x10000`.

## Honest notes

**The flash fix is bench-proven on real hardware** — two live flashes, both clean, with the 12.6 s erase measured and logged. The sleep and rescue work was verified on the bench too, against a connected PCM.

**One gap is deliberately still open.** If Wi-Fi or NC Flash drops out during the one to four minutes it takes to write the program, the adapter still stops the flash. This release makes that window much narrower; it does not close it. Keep the laptop near the car.

**Fault-code reads and ROM reads still leave no trace in the log.** You will see that a host claimed the bus, not what it did with it. That is being worked on separately.
